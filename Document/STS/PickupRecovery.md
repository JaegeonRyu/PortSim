# STS 선박 추종과 안전한 체결 재접근

STS가 파도로 움직이는 컨테이너를 찾았지만 네 모서리의 위치·상대속도 조건을 유지하지 못하면, 잠금 없이 정렬 시도만 소진할 수 있다. 이 실패를 곧바로 터미널 전체 정지로 전파하지 않도록 미인양 작업의 복구를 구분한다.

## 동작

- 접근부터 체결까지 같은 감쇠된 트롤리/현수체 제어를 사용한다. 긴 다음 작업 이동에서도 기존 예약 작업 범위를 유지한다.
- 체결 단계는 센서에서 얻은 컨테이너 위치·속도·가속도·jerk와 그 시간 변화로 이동하는 현수 기준을 계산한다. 바람 평형과 로프 길이 변화도 반영한다.
- Pitch/Roll은 측정 자세와 각속도를 추종하는 등가 보정 구동기로 진행한다. 화물 자세를 스프레더에 즉시 복사하거나 컨테이너를 목표 위치로 옮기지 않는다.
- 회전까지 포함한 각 모서리의 실제 위치 오차와 측정 상대속도를 검사한다. 수평 3 cm, 수직 2 cm, 연속 착좌 0.7초, 네 잠금 피드백과 시험 인양 조건은 유지한다.
- 자세 보정 토크와 실제 텔레스코픽 모서리 간격을 간이 네 와이어 힘/모멘트 배분에 전달한다.

## 국소 복구

복구 대상은 `AlignmentExhausted`로 분류된 정렬 소진뿐이다. STS 하역 중이며 화물이 여전히 선박 소유의 고정 화물이고, 매달리거나 다른 액터에 부착되지 않았으며 센서가 유효한 경우에만 시작한다.

1. 화물을 움직이지 않고 잠금 해제를 요청한다. 구동 시간과 네 잠금 해제 피드백을 확인하기 전에는 후퇴하지 않는다.
2. 움직이는 선박을 추종하면서 각 모서리의 간격이 최소 0.5 m인 위치까지 후퇴한다. 예약 높이와 구동 한도는 유지한다.
3. 새로운 센서 관측에서 간격·상대속도가 2초 동안 안정적인 것을 확인한 뒤 같은 화물을 다시 취득한다. AGV, 화물 ID·질량·소유권·야드 예약을 바꾸지 않는다.
4. 최대 두 복구 주기 후에도 체결되지 않으면 다시 해제·후퇴를 확인하고 해당 STS를 `PickupUnavailable`로 격리한다. 기존 재배정 계획기가 레일·도달 범위 조건을 지키며 대체 작업을 판단한다. 대체할 수 없으면 해당 작업을 유지하고 수동 복구를 기다린다.

매달린 하중, 잠금 확인 실패, 과부하, 충돌, 로프 모델 한계 초과 등은 이 복구 경로로 무시하지 않는다. 해제·후퇴의 안전 조건을 확인하지 못하면 기존 안전 정지를 유지한다. 재접근 기록은 웹 이벤트 이력에 남기고 현재 단계·실제 Pitch/Roll·보정 토크를 장비 상세에 제공한다.

## 설정과 모델 범위

`STS_Simulation.json`의 `pickup_control.attitude_control`과 `pickup_control.recovery`에서 설정한다. 기본 자세 한도는 ±2°, 각속도 2°/s, 각가속도 6°/s², 축별 토크 30,000 N·m다. 이 값과 1.5 m 등가 무게중심 깊이는 **시뮬레이션 가정값**이며 제조사 검증 수치가 아니다. 독립 유압 회로·각 로프의 탄성 접촉을 푸는 모델은 아니다. 기존 RMG 프로파일에는 자세 보정·STS 복구를 자동 활성화하지 않는다.

설정이 없는 프로파일은 자세 보정과 추가 복구를 비활성 상태로 읽는다. `recovery.max_cycles: 0`으로 추가 복구를 끌 수 있다. 배속은 제어 한도나 허용 오차에 곱하지 않는다.

## 무거운 화물의 호이스트 감속 여유

RMG가 29.3 t 화물을 내릴 때 정격 전력을 정상 하강에 모두 소비하면, 기존 전력 기반 토크 제한에서 감속 가능한 가속도가 0이 될 수 있었다. 이 상태에서는 착지 높이에 도달해도 하강을 멈추지 못하고 기계적 하한에서 단계 시간 초과가 발생했다.

호이스트 속도는 이제 실제 총질량(스프레더 포함), 드럼·기어·로핑, 효율, 모터 관성·최대 토크·RPM 및 정격 전력으로 제한한다. 설정 가속도 중 모터가 낼 수 있는 토크를 감속 여유로 확보한 상태의 전력 한도를 사용한다. 정격 전력이나 착지 허용 오차를 늘리지 않는다. 계산된 전력 기반 속도 상한은 `hoist_power_speed_limit_mps`로 내보낸다.
