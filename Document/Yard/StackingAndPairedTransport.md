# 물품 기반 야드 적재와 20ft 묶음 운송

작업 시작 기준: upstream main `e1ee639` (2026-10-14에 fast-forward로 반영).

## 가상 운송 예약

`FPortCargoInformation`에 물품, dry/reefer, 위험물 모의 그룹, 출고 순서, 목적항·기항 순서, 온도, 상부 적재 허용 중량을 넣는다. 기계 부품·강재·전자제품·의류·가구·냉동식품·청과·인화성 도료·부식성 세정제 예시를 사용한다. 20ft는 기계 부품 예약 그룹으로 구성한다. 기존 크기별 자중·화물중량·무게중심 입력은 보존한다.

전체 운용 화물의 크기 비율은 **20ft 28%, 40ft 70%, 45ft 2%**다. 기본 600개는 **168/420/12개**다. 다른 수량은 최대 나머지 방식으로 정수 배분해 합계를 보존한다. 크기는 선박·STS 스트림에 섞어 배분하며, 자중·화물중량은 해당 크기의 기존 모의 입력을 사용한다.

물품과 예약 정보는 `synthetic_simulation_booking`이다. 위험물 분류는 인화성/부식성 모의 그룹이며, 실제 UN 번호·IMDG 격리표를 대신하지 않는다. 상부 적재 허용 중량 180t 역시 CSC 명판을 확인한 값이 아닌 모델 가정이다.

## 야드 배정

1. 선박의 현재 취급 가능한 상부 화물부터 계획한다. 예약된 두 번째 화물이 아직 선박에 있으면 그 아래 화물의 선행 픽업을 금지한다. 다음 선창 배치는 이전 배치 하역 이후 사용한다.
2. dry 일반 화물은 출고 순서 1/2/3/4에 따라 야드 1~5/6~10/11~14/15~18로 나눈다. 이 배치는 남측 출구를 가정한 모의 출고 동선이다.
3. 야드 19~21은 냉동·냉장 예약 전용, 22는 인화성 모의 화물, 23은 부식성 모의 화물 전용이다. 냉동 구역 지정은 적재 위치 제약이며 전력·온도 유지 물리까지 구현한 것은 아니다.
4. 같은 스택은 동일 크기·취급 타입·위험물 그룹만 허용한다. 상부 출고 번호가 하부보다 크면 배정을 거절하므로 먼저 출고할 화물을 뒤늦게 출고할 화물이 덮지 않는다.
5. 상부 총중량은 하부 총중량 이하로 제한한다. 모든 하부 컨테이너의 누적 상부 중량 한계를 확인한다. 기존 상부 화물과 맞지 않는 무거운 화물은 새 바닥 슬롯으로 보낸다.
6. 허용 후보 중 호환 스택 재사용, 운송 거리, RMG 예상 대기량을 고려한다. 하부가 실제로 적재된 다음 상부 운송을 배차해 RMG 입구에서 지지 화물을 기다리는 교착을 피한다.

### 크기별 전용 칸과 20ft 두 자리

현재 9-STS 모드의 모든 취급·출고 구역 안에서 Bay 1/19는 20ft 전용, Bay 29는 45ft 전용, 나머지 운영 베이는 40ft 전용이다. 다른 크기는 해당 베이에 배정할 수 없으며, 20ft 두 개 위에 40ft를 올리는 적재도 허용하지 않는다.

20ft 한 칸은 40ft 길이(12.192m) 안에 앞·뒤 두 자리를 둔다. 각 화물 길이는 6.058m, 자리 중심은 칸 중앙에서 ±3.067m, 가운데 간격은 7.6cm다. 가로로 두 대를 나란히 놓는 방식이 아니라 **긴 방향으로 두 개**를 놓는다. 각 자리는 독립된 ID·중량·받침·예약·센서 인계를 유지한다. 두 아래 자리가 모두 실제 적재된 뒤에만 다음 층 운송을 허용하며, 같은 자리의 아래 20ft보다 가벼운 화물만 올린다. 한 층의 남은 자리를 우선 채우고, 수량이 홀수이거나 순차 인계 중이면 마지막 층의 한 자리가 잠시 비어 있을 수 있다.

RMG는 두 자리에 각각 내려놓는다. AGV의 조건부 두 개 운송과 야드의 두 자리 구조는 별도 규칙이다. 웹에 크기별 전체 개수와 화물별 칸 ID·자리 1/2·층을 표시하며, CSV에도 칸·자리·전용 크기·실제 목표 좌표를 남긴다. 야드 수용량은 이 배치에서 컨테이너별 자리 수를 합산한다.

받침 화물의 계획 하역 순서는 상부 화물보다 반드시 빠르다. 묶음 후보를 먼저 계획했더라도 그 후보의 정상 하역 순서보다 앞선 화물의 받침으로 사용할 수 없다. 이 조건을 전체 계획 검증에서도 검사한다. 제한 수량 운용은 이 순서의 앞부분을 선택해 검증 범위 밖의 받침을 기다리지 않는다. 야드 인수와 받침이 준비된 STS에만 빈차의 직접 복귀를 배정한다.

전체 최적해를 보증하는 방식은 아니다. 예약·지원 조건을 먼저 만족시키는 결정적 휴리스틱이며, 사용할 수 있는 슬롯이 없으면 오류를 반환한다. 기존 8-STS 모드는 종전 계획을 유지하고 이 규칙은 현재 9-STS 통합 운용에 적용한다.

## 20ft 두 개 운송

같은 STS의 같은 선창 배치·상부 층, 같은 출고 그룹·취급 타입, 일반 화물, 같은 RMG·인수 위치를 갖는 20ft 두 개를 후보로 만든다. 합산 중량은 AGV 65t 정격 이내여야 하며 갑판에서 서로 겹치지 않아야 한다. 다른 STS의 적재 출차 경로를 막는 인수 위치에서는 묶음 운송을 사용하지 않는다.

AGV의 긴 축 기준 -3.067m와 +3.067m에 두 화물을 놓는다. 각 컨테이너 길이 6.058m와 7.6cm 사이 간격을 포함한 전체 길이는 12.192m다. STS는 각 화물을 따로 정렬·착좌·4개 잠금·시험 권상하여 같은 AGV에 싣는다. RMG도 같은 인수점에서 두 화물을 따로 검증해 각각 계획 슬롯에 적재한다. 8개 잠금을 갖춘 twin-lift 스프레더로 동시에 드는 모델과 구별한다.

모의 절감 시간은 `한 번의 추가 적재 주행 + 빈차 복귀 - 두 번째 픽업 대기 - 추가 취급 시간`이다. 거리에는 해당 STS의 필수 횡단 도로, 근거리/내륙 서비스 종축, RMG 진입·복귀와 대기열 접근을 포함한다. 원거리 RMG의 서비스 도로를 가로질러 가는 직선 거리로 계산하지 않는다. 초기 대기 추정은 150초, 추가 취급은 15초, 최소 절감 기준은 30초다. 첫 실제 STS 서비스 시간에서 AGV 미도착으로 멈춘 시간을 빼 재평가하고 기준을 충족하지 못하면 개별 운송으로 돌아간다. 값은 실측 장비 성능이나 전체 항만 makespan 절감 보증이 아니다.

두 화물은 ID·질량·위치·소유권·인계 기록을 각각 유지한다. AGV 구동에 쓰는 적재 중량과 무게중심은 현재 차량에 붙어 있는 화물들을 합산한다. RMG가 집어 든 화물은 차량 하중에서 제외된다. 실제 STS 서비스 시간의 재평가에서는 수평 이동 완료 뒤의 대기뿐 아니라, 5단계에서 AGV 미도착으로 하강이 금지된 시간도 차감한다.

첫 화물 적재 뒤에는 완료된 주행 경로를 재사용한다. 두 번째 화물의 RMG 예약은 실제 인수점 정차와 속도, 같은 인수점의 접근 소유권을 검사한다. 주행 경로의 끝에서는 실제 끝점과 정차를 확인하고 추가 주행 명령을 만들지 않는다.

## 선박 적재 계획 미리보기

현재 운송 운용은 선박에서 야드까지다. 별도 `PlanShipStowage`는 야드 화물을 선박에 실을 계획을 생성하며, 액터 이동을 시작하지 않는다.

- 나중 기항할 목적항 화물을 먼저 아래에 두고, 같은 기항 순서 안에서는 무거운 화물을 먼저 배치한다. 상부에 더 늦은 기항지의 화물, 더 무거운 화물, 다른 크기·취급·위험물 그룹을 두지 않는다.
- 각 후보에서 `KG = 전체 수직 중량 모멘트 / 배수량`, `GM = KM - KG - 자유수면 모멘트 / 배수량`을 계산하고 GM 범위·횡경사 한계를 확인한다. 횡중량 모멘트를 줄이는 배치를 선택한다.
- 스택 중량·각 하부 컨테이너의 상부 중량 한계, 횡가속에 의한 정적 전도 모멘트를 네 고박 지점에 분배한 하중 추정 한계를 검사한다.
- `PortSim/Config/Stowage_Planning.json`의 경하중량·KG·고정 KM·자유수면 보정·GM·스택·고박 한계는 **명시적인 모의 제원**이다. 실제 선박의 배수량별 KM 곡선, GZ 곡선, 트림·종강도, 동적 항해 조건, Cargo Securing Manual을 대신하지 않는다.

## 웹과 보고서

컨테이너 상세 화면에서 물품·취급·위험물·출고·목적항·계획 층·묶음 후보를 본다. AGV는 적재한 각 화물의 링크·중량과 합산 무게중심을 표시한다. 선박 상세에는 적재 계획의 실행 가능 여부, 보정 GM·횡경사·스택·고박 한계, Bay/Row/Tier 배치표를 표시한다.

작업 CSV는 기존 시간·질량 필드와 함께 예약 정보, `TripID`, `TripCargoOrdinal`, `PairedTrip`, 추정 절감 시간, 계획 층과 하부 컨테이너 ID를 저장한다. 실제 기준 운용 대비 시간 절감으로 표시하지 않는다.

## 이전 정책 검증 기록 (20ft 칸 분할 전)

최신 main과의 통합 과정에서 대기 베이 함수 선언 누락·인계 준비 함수 중복 정의를 정리하고, 공유 픽업 검사에 필요한 RMG 수평 상대속도(0.05m/s)·시험 권상 수평 허용치(0.1m) 설정을 보완했다. 일시정지·비상정지 시 환경 시간과 선박·화물을 함께 정지시키며, 권상 상부 예약 경계에서는 모터 가속도와 남은 스트로크로 제동한다. 선박 운동은 렌더 프레임에서 한 번 보간하고 고정 제어 단계의 구간으로 나눈다. AGV에 실린 화물은 선박 시절의 운동값 대신 차량의 이동·조향 속도를 사용한다. 센서 정렬·잠금·시험 권상·실제 차체 검사와 안전 정지 조건은 유지한다.

수평 구동은 목표 주변에 픽업 획득 반경의 절반을 anti-sway 보정 공간으로 두고, 남은 거리·상대속도·모터 가속도와 다음 제어 단계의 이동량으로 제동한다. 보정 가속도를 없애거나 예약 영역을 넓히지 않는다. 최대 속도로 양쪽에서 접근하는 검사에서 보정 구간 유지·가속도 제한·작은 anti-sway 보정 유지가 통과했다.

대각선 구동의 합성 흔들림은 측정한 두 축 각·각속도, 와이어 길이·권상 속도, 바람 하중 추정과 실제 축 가속도로 각방향 제동 거리를 계산한다. 센서 각도 범위와 예약 이동 영역에서 허용하는 흔들림 중 작은 범위 안에서 감속하며, 범위는 변경하지 않는다. RMG 설정과 실제 현수 물리 모델을 사용한 강풍·대각선 가속 검사에서 센서 범위·가속도 제한과 전진을 확인했다. 센서 오류 로그에는 유효하지 않은 센서 이름·값·허용 범위와 관측값 나이를 남긴다.

시험 권상은 목표로 이동·정착하는 예산(`trial_lift_timeout_s`, 90초)과 정착 후 하중을 확인하는 예산(`trial_timeout_s`, 기존 60초)을 분리한다. 90초는 기존 정렬 예산 이내의 상한이며 추가로 기다려야 하는 시간이 아니다. 위치·속도·4개 잠금·지지 해제·모서리 하중·안정 유지 기준은 변경하지 않았다. 새 설정이 없는 파일과 프로그램에서 직접 만든 설정은 종전 제한 시간을 사용한다.

Unreal Editor 타깃 빌드가 성공했다. `PortSim.Stowage`의 야드 적재·선박 GM/스택/고박·묶음 운송 경제성·수평 제동·합성 흔들림 제동·시험 권상 시간 구분 검사 총 6개와 웹 테스트 9개가 통과했다. PowerShell 검증 스크립트 문법 검사도 통과했다.
