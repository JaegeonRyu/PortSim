# 적재 AGV 고장 시 R/S 인계

기준일: 2026-11-03. 현재 작업 트리의 구현 범위와 검증 이력을 구분해 기록한다. R/S(Reach Stacker, 리치 스태커)는 기본 배치 4대다.

## 사용 방법

1. 갱신된 엔진으로 시뮬레이션을 실행하고 대시보드를 새로고침한다. 저장된 과거 기록에서는 제어할 수 없다.
2. 컨테이너를 운반하는 AGV의 **오류·돌발상황**에서 주행 고장을 적용한다.
3. 차량이 정지한 뒤 수리가 오래 걸린다고 판단하면 **새 AGV 배정 · R/S 인계**를 누른다. 수리 시간 임계값에 의한 자동 배정은 구현하지 않았다.
4. 대체 AGV와 R/S의 현장 이동, 인양, 이송, 안착, 작업 승계 상태를 확인한다. 가용 장비나 접근 경로가 없으면 명령이 거부되며 사유를 표시한다. 조건을 확보한 뒤 다시 배정한다.

배정 대상은 화물을 실제로 소유한 정지 AGV다. 하역 운송/야드 진입 대기 단계(3·9), 선적 복귀/STS 접근 단계(5·6)를 지원한다. 진행 중인 크레인 인계, 돌발상황 또는 이미 진행 중인 R/S 복구 작업이 있으면 새 배정을 거부한다.

## 처리 흐름

고장 AGV의 운송 작업을 유지하면서 빈 정상 AGV와 사용 중이 아닌 R/S를 선택한다. 두 AGV는 복구 중 일반 배차에서 제외된다. 대체 AGV는 기존 FMS 이동·교통 예약을 사용하고, R/S는 복구 도로 경로를 따라 저속으로 이동하며 차량 간섭 시 기다린다.

정지 위치를 확인한 뒤 화물을 한 개씩 고장 AGV → R/S → 대체 AGV로 부착·분리한다. 소유권은 `AGV → ReachStacker → AGV`로 바뀐다. 붐·스프레더 위치와 화물 인양·수평 이송·하강을 연속적으로 갱신한다. 두 개의 20ft 컨테이너도 순차 처리한다.

모든 화물이 안착하고 원래 경로에 재진입할 경로를 확보한 뒤 기존 작업·목적지·Trip ID·STS/야드 접근권·관련 크레인의 인계 차량 참조를 새 AGV로 넘긴다. 화물 인계 후 재진입 경로가 없으면 완료로 처리하지 않고 대기한다. 기존 차량의 주행 고장은 인계만으로 수리되지 않는다.

대체 AGV 고장이나 돌발상황에서는 화물 상태를 유지하고 기다린다. 복구 중 추가 고장/돌발상황 명령은 제한하며 수리 명령은 허용한다. 전체 일시정지 중에는 복구 이동과 인계를 진행하지 않는다. 복구 중 체크포인트 예측 재생은 비활성화한다.

## 대시보드

| 위치 | 표시 내용 |
|---|---|
| 장비 분류·탐색기 | `R/S` 필터, 장비 번호, 상태, 운반 하중, 복구 상태 |
| 오버뷰 상단 | 운영 장비 수와 작업 중 장비 수에 R/S 포함, 유형별 R/S 수량 |
| 오버뷰 지도 | 주황색 R/S 차체·장비명·범례, 선택 시 상세 연결 |
| R/S 개요 | 개념 도식, 복구 상태, 인양 한도 가정, 고장/대체 AGV 링크 |
| AGV 상세·이력 | 배정 버튼, 인계 진행 수량, 출동·인양·안착·승계 이벤트 |
| 화물 상태 | `ReachStacker`를 R/S 인양·인계로 표시 |

표시 수량은 엔진 액터 집계다. 오래된 스냅샷에는 `rs` 유형과 복구 필드가 없을 수 있다.

## 모델 가정과 남은 범위

- R/S는 블록아웃 운동 모델이다. 최대 인양 질량 45t/개, 현장 주행 2m/s, 수평 이송 0.6m/s, 수직 이동 0.4m/s를 코드 가정으로 사용한다. 제조사 제원에 따른 붐 반경별 하중표가 아니다.
- 정렬·잠금 대기 3초와 안착 확인 2초는 상태 전이 타이머다. 독립 센서의 네 코너 접촉·잠금 피드백, 시험 인양 하중 검증을 재현한 것은 아니다.
- R/S 타이어/유압/전도 안정성, 집게 마찰·미끄러짐, 센서 가림·고장 모델은 미구현이다. R/S 이동과 화물 인계는 기구학적 위치 갱신과 강체 부착으로 처리한다.
- 복구 접근 경로는 기존 도로와 국소 연결을 사용한다. 모든 현장 위치·회전 자세·혼잡 상황에서 진입/복귀가 성립함을 보장하지 않는다. 센서·접촉 기반 안전 인계와 전체 운송 완료 검증은 남아 있다.
- 전용 취소 버튼과 복구 완료 후 R/S의 자동 원위치 복귀는 없다. 진행 중 복구 초기화 시 R/S 위치를 저장한 시작 위치로 복원하고, 일반 초기화 절차에서 화물을 재배치한다.

## 검증 기록

2026-11-03 초기 구현에서 UE 5.6 Development Editor 빌드 성공, `PortSim.Recovery.` 자동화 4개 및 Dashboard 테스트 36개 통과를 확인했다. 초기 R/S 테스트는 현장 도착 이후 인계·작업 승계를 중심으로 검사했으며, 실제 출동부터 최종 목적지 완료까지의 통합 운송 증거는 아니다. 엔진 로그: `PortSim/Saved/Logs/LoadedRecoveryTest.log`.

이후 단일 소유권 검사, 접근 경로 보완, R/S 장비·오버뷰 표시를 추가했다. 사용자 요청으로 이후에는 테스트를 실행하지 않고 빌드만 확인했다. 최종 UE 빌드는 성공했으며, 마지막 웹 오버뷰 수정 시 엔진 빌드는 `Target is up to date / Result: Succeeded`였다. 이 결과는 웹 화면 렌더링 검증을 의미하지 않는다. 추가된 테스트 코드가 존재하는 것과 최종 변경으로 재실행해 통과한 것은 구분한다.

### 접근 경로 오류 보완 (2026-11-03)

실행 중 AGV-100 고장 기록에서 빈 정상 AGV와 R/S 4대가 있는데도 배정이 거부되는 사례를 확인했다. R/S 경로의 고장 차량 간섭 검사에 AGV와 동일한 차체 크기를 사용하던 부분을 수정하고, R/S 9m × 3.4m 검사 외피와 상대 AGV 외피를 별도로 적용했다. 정지 후 미세한 조향 오차는 도로 그래프 연결용 축에만 보정하며 실제 차량 자세를 이동시키지 않는다. 회전 곡선을 만들 수 없는 짧은 진입 연결은 제외한다.

거부 사유는 빈 정상 AGV 부족, R/S 부족, 대체 AGV 경로 부족, R/S 경로 부족으로 구분한다. 사용자 요청에 따라 이 보완은 테스트를 실행하지 않고 빌드로만 확인하며, 실제 출동·인계 성공을 확인한 기록은 아니다.
