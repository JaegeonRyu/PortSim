# 돌발상황 시간 기록

실시간 돌발상황 관리 페이지의 터미널 오버뷰 아래에서 기록과 시간 분석을 확인한다. 이전 시간 절감 분석 메뉴와 사람 운전 시간 수동 입력은 제거했다.

## 측정

- `incident_timing.clock_seconds`: 실행 중 엔진이 진행한 시뮬레이션 초. 오류·비상정지·기상 대기는 포함하며 수동 일시정지와 시작 전/실행 종료 후 시간은 제외한다. 브라우저 시계나 실제 컴퓨터 처리시간으로 계산하지 않는다.
- `halt_seconds`: 전체 물리/운용 정지 구간의 경과시간. 동시에 원인이 여러 개여도 한 번만 누적한다. 개별 장비들의 정지시간 합계가 아니다.
- 단계별 `measurement_applied_at`, `fault_cleared_at`, `work_resumed_at`, `work_completed_at`: 실제 오류 적용, 해당 고장 상태 해제, 관측된 작업 진행 재개, 해당 화물의 후속 작업 완료 시각이다. 수리 요청 접수만으로 작업 재개를 주장하지 않는다. 인접 STS가 재배정된 화물의 작업을 실제 재개하면 원래 STS의 수리 전에도 재개 시각을 기록할 수 있다.
- 발생 전 단계/이전 엔진 기록에는 시간값을 만들지 않는다. 시간 초과가 나도 발생한 고장의 시간 추적은 계속하며, 검증 통과로 바꾸지 않는다.
- 영향 장비/화물은 직접 대상, 재배정 이벤트, 관측된 FMS 차단 의존 관계 및 장비 대기로 확인한 누적 집합이다. 같은 대상은 중복 집계하지 않는다. 이것은 모든 간접 영향을 완전히 증명한 인과 그래프가 아니다.

## 정상 기준과 비교

1. 오류나 실행 중 날씨 변경 없이 정상 운반을 실행한다. 일부 컨테이너라도 야드 적재가 완료되면 **현재 정상 기록을 기준으로 저장**할 수 있다.
2. 같은 코드·설정·초기 컨테이너 및 야드 계획·장비 설정·환경 시드/초기 상태로 새 실행을 시작하고 돌발상황을 발생시킨다. 다른 무작위 날씨를 비교하지 않도록 명령줄의 `-PortSimEnvironmentSeed=166290927` 등 고정 시드를 사용한다. 환경 상태가 계속 진행한 기존 월드의 리셋은 새 초기 환경과 일치하지 않을 수 있다.
3. 코드와 설정/초기 상태의 지문이 다르면 비교를 거절한다. 정상 기준은 브라우저 localStorage에 조건별 최대 5개를 저장한다. 현재 실행 자체를 기준과 비교하지 않는다.
4. 저장된 기준의 **동일 컨테이너 ID 집합**에 대해 마지막 야드 적재 완료 시각을 비교한다. 각 실행에서 먼저 완료한 서로 다른 120개를 비교하지 않는다. 부분 기준이면 물량 수와 부분 기준임을 표시한다. 현재 비교 범위는 선박에서 야드로 이동하는 수입 컨테이너다.
5. 추가시간 = 오류 실행의 같은 물량 완료 시각 − 정상 실행 완료 시각. 증가율 = 추가시간 / 정상 실행 완료 시각 × 100. 음수도 그대로 표시한다. 개별 컨테이너 지연이나 여러 오류의 시간을 합산해 전체 지연을 만들지 않는다.
6. 미완료 물량은 최종 추가시간/증가율을 확정하지 않는다. 정상 완료시각을 이미 넘겼다면 현재 경과를 이용한 **최소 추가 지연**만 표시한다. 비교 근거가 없으면 ‘비교 기준 없음’으로 남긴다.

단계의 영향 화물 최대 추가 지연은 그 화물이 실제로 겪은 결과의 비교이며, 여러 고장이 겹쳤을 때 한 고장만의 순수 효과가 아니다. 한 오류만의 효과를 분리하려면 그 오류만 제외한 추가 비교 실행이 필요하다.

**시간 기록 내려받기**로 현재 실행의 시계·단계 기록·기준·비교 결과를 JSON으로 저장할 수 있다. 화면 새로고침은 엔진 리셋이 아니며, 실시간 연결이 끊기면 마지막 엔진 시각에서 시간이 멈춘다.

## 검증 · 2026-11-11

- UE 5.6 최종 빌드 성공, 최종 엔진 자동화 64개 및 웹 테스트 58개 통과. 수동 일시정지 제외, 안전/기상/비상 정지 포함, 동시 정지 중복 방지, 수리와 실제 작업 재개 구분, 즉시 재배정의 영향 기록, 화물 완료 후 장비 수리 시각, 조건 불일치/부분 물량/미완료 비교를 확인했다.
- 실제 HTTP 명령으로 적재 AGV에 FMS 통신 단절을 주입했다. 발생 638.8초, 고장 해제와 주행 재개 647.0초, 해당 화물 최종 야드 완료 867.0초를 기록했다. 고장/복귀 간격 8.2초와 후속 작업 완료까지 228.2초는 서로 다른 지표이며, 정상 대비 순수 추가시간으로 주장하지 않는다. 정상 기준 생성 후 동일 실행 비교 거절 및 오류 실행의 정상 기준 저장 거절도 확인했다.
- 동일 실행에서 600개 중 120개를 연속 운반했다. 120개 ID가 모두 고유하며 장비 오류·순환 교착 복구 없이 종료했고 물리 배치·일시정지/E-stop·초기화 검사도 통과했다. 해상운동을 제외한 고정 시드 장면이다. 이후 보완한 즉시 재배정/완료 후 수리 기록은 최종 64개 자동화에서 재확인했다.
- 앱 의존 모듈 15개 HTTP 응답 확인. 실제 브라우저 화면 자동 조작은 Windows에서 현재 URL 확인이 불가능하다는 보안 제한으로 중단했으며 시각 검증을 완료했다고 주장하지 않는다.
