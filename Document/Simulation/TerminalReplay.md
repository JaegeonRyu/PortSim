# 고정 간격 순방향 배속

기준일: 2026-11-05.

## 계산과 지연 처리

통합 터미널의 배속은 환경·제어를 순서대로 진행하고 자유 강체가 있을 때 매 단계 Chaos 결과를 반영하는 **1/60초 순방향 계산**을 사용한다. 배속을 위해 미래 체크포인트를 만들거나 복원하지 않는다. 기존 50ms 물류 스케줄러와 크레인 내부 제어·현수체 적분 간격은 유지한다.

- `PortSim.LivePhysicsMaxSteps`: 기본 64, 범위 1~120. 엔진 프레임당 최대 계산 단계 수.
- `PortSim.LivePhysicsBudgetMs`: 기본 50ms, 범위 1~100ms. 완료한 단계 뒤에 시간을 확인하므로 한 단계 비용만큼 초과할 수 있다.
- 벽시계 경과 시간 × 유효 배속을 누적하되 최대 단계 수 × 1/60초까지만 유지한다. 초과 벽시계 수요는 폐기한다. 계산 단계 자체를 건너뛰거나 물리 시간 간격을 확대하지 않는다.
- 시간 예산으로 처리하지 못한 제한 내 잔여 수요는 다음 화면으로 이월한다. 성능이 부족하면 실제 달성 배속이 내려간다.
- 완료한 묶음 뒤에 선상 화물 위치와 로프 표시를 갱신하고, 대시보드는 별도 벽시계 주기와 비동기 쓰기 정책을 유지한다.
- 묶음 실행 후 바깥 월드 물리 프레임은 0초로 동기화하여 중복 적분하지 않는다.

외부 입력은 누적 수요를 초기화하고 기존 입력 대기 정책을 적용한다. 일시정지 시간을 재개 후 몰아서 실행하지 않는다.

## 화물 분류와 충돌 후보

`UPortCargoBody`가 물리 활성화와 결합·분리 변경을 감지한다. 생성·종료 시점도 반영하여 자유 강체(`FreeCargo`), 장비에 결합해 이동하는 화물(`MovingCargo`), 고정 화물(`FixedCargo`)을 관리한다. 바람은 자유 강체 목록에, 차량 적재 질량 계산은 이동 목록에 집중한다. 고정 야드 화물의 충돌은 기존 Chaos 공간 분할을 사용하며 반복 위치 갱신은 하지 않는다.

선상 화물은 원래 선박 기준 배치 좌표를 보존한다. 선박 운동의 이전·현재 상태를 공통으로 저장하고, 실제 화물의 운동 보간과 물리 위치 갱신은 작업 대상·질의 후보·표시 시점에 수행한다. 중간 계산에서 모든 선상 화물을 이동시키지 않는다.

선박별 배치 구역을 20m 셀로 묶고 구역 경계를 공간 인덱스에 등록한다. 보간 경로의 Hermite 제어점, 회전 범위, 이전 물리 위치를 포함한 보수적인 경계로 후보를 찾는다. 센서 질의 직전에는 해당 화물의 정확한 위치를 동기화한다. 화면 표시 후 과거 경계를 정리하므로 장시간 실행 중 검색 범위가 계속 커지지 않는다. 화면 가시성은 후보 제외 조건으로 사용하지 않는다.

자유 화물의 이동 경로 주변과 관리되는 R/S 강체 주변의 선상 충돌 후보는 각 물리 단계 전에 동기화한다. 수면 중인 자유 강체도 포함한다. Chaos가 실제 접촉과 활성·수면 강체 처리를 담당한다.

## 외부 물리와 체크포인트

묶음 진입 시 월드의 물리 구성 요소를 확인한다. 지원 대상은 터미널 화물의 실제 본체와 관리되는 R/S 물리 본체다. 외부 강체, 네트워크 월드, 비동기 물리, 물리 예측 등 지원하지 않는 조건에서는 일반 엔진의 고정 단계 경로를 사용하고 누적 배속 수요를 폐기한다. `PortSim.BufferedPlayback=0`, `PortSim.BatchLivePhysics=0`, `-PortSimNoReplay`도 일반 고정 단계 대체 경로를 선택한다.

`FTerminalCheckpoint`의 명시적 캡처·복원 기능은 유지하며 화물 분류·공간 인덱스·공통 운동 상태도 함께 보관한다. Chaos 내부 이력의 복원은 지원하지 않는다. 배속용 미래 버퍼는 제거했으며 대시보드 호환 필드 `BufferedSeconds`는 0이다.

주요 모드는 `live`, `live_input_hold`, `live_physics_batch`, `live_external_physics`다. 실제 배속은 벽시계 대비 진행한 시뮬레이션 시간으로 측정한다.

## 확인 범위

이번 변경은 사용자 요청에 따라 자동화 테스트와 실행 테스트를 수행하지 않는다. 확인 범위는 UE 5.6 `PortSimEditor Win64 Development` 빌드이며, 장시간 처리량과 실제 동작은 별도 실행 검증 대상이다.

## 2026-11-05 배속 처리 비용 보완

이전 변경은 자유 강체가 없는 구간에도 매 단계 전체 Chaos 솔버를 실행했고, 매 화면마다 화물 분류와 운동 캐시를 다시 갱신했다. 두 반복 비용을 줄였다. 터미널 소유 화물은 생성·해제·결합 콜백으로 목록을 유지하며 외부 화물만 진입 시 보정한다.

자유 화물·R/S 자유 강체가 없을 때는 1/60초 모델 계산과 센서 질의를 진행하되 강체 적분은 생략한다. 제어 단계 직후 해제 여부를 다시 확인하고 자유 강체가 있으면 해당 단계부터 Chaos를 실행한다. 수면 중인 자유 강체도 제외하지 않는다. 생략 구간 후에는 누적된 장비 위치 목표를 동기화하여 오래된 위치 이동이 다음 물리 프레임에 재생되지 않도록 한다. 외부 액터가 묶음 중 생성되면 물리를 실행한 뒤 묶음을 종료하고 다음 프레임에서 다시 적합성을 확인한다. 알 수 없는 물리 구성 요소와 `-PortSimFullPhysics`는 솔버를 유지한다.

공통 계산 예산 기본값은 8ms에서 25ms로 조정했다. 최대 16단계와 지연 수요 상한은 유지한다. 프로파일에 `forward_frame`, `forward_chaos_step`, `forward_kinematic_commit`을 추가했다. 실행 테스트를 하지 않았으므로 실제 배속 개선 수치는 미측정이다.
## 2026-11-05 프레임당 처리량 상한 개선

화면 한 프레임당 16단계 제한에서는 30fps일 때 최대 8배속, 20fps일 때 최대 약 5.33배속이다. 물리 계산이 충분히 빨라도 60fps 미만에서 16배속을 유지할 수 없었다. 기본 단계 상한을 64, 계산 예산을 50ms로 변경했다. 모든 단계는 여전히 1/60초이며 최대 누적 수요는 단계 상한 × 1/60초다. 계산 예산은 단계 종료 시 확인하므로 한 단계의 비용만큼 초과할 수 있다. 예산 확대로 입력 응답과 화면 프레임이 낮아질 수 있으나 계산 간격을 확대하거나 결과를 건너뛰지는 않는다.

정지한 차량·예약 구역은 동일한 공간 경계의 셀 목록을 다시 만들지 않는다. 자유 강체가 없는 구간의 표시 후 동기화에서도 위치가 바뀌지 않은 충돌체에 물리 변환을 반복 적용하지 않는다. 자유 강체가 처음 등장하는 전환 지점은 캐시와 무관하게 동기화한다. 배속 드라이버가 맡는 물리 장면 설정을 각 물류 단계에서 중복 호출하지 않도록 했다.

배속 실행 중 5초마다 `PORTSIM_PLAYBACK_COST` 로그를 남긴다. 요청·실제 배속, 프레임당 처리 단계, 단계당 제어/물리 비용, 프레임 부대 비용, 배속 함수 밖의 경과 시간, 시간/단계 상한 도달 횟수와 폐기된 벽시계 수요를 구분한다. `outside_batch_ms`에는 렌더링뿐 아니라 나머지 엔진 작업과 대기 시간도 포함되므로 GPU 시간으로 해석하면 안 된다. 중지·입력·대체 경로 전환 시 집계를 초기화한다.

16배속은 실제 초당 960개의 고정 단계를 처리해야 하므로, 모델 계산 자체가 하드웨어 처리량을 초과하면 유지할 수 없다. 이번 변경은 구조적인 프레임당 상한과 반복 비용을 줄인 것이며, 사용자 요청대로 실행 테스트를 하지 않아 16배속 유지 여부는 미검증이다.
## 2026-11-05 크레인 해제·안정화 구간의 물리 비용

사용자 실행 로그에서 약 3.4배속 구간은 모델 계산 약 1ms/단계, 물리 처리 약 2.5ms/단계였고 거의 모든 프레임이 계산 예산에 도달했다. 물리 호출이 없는 구간에서는 약 15.5배속을 기록했다. 이는 물리 작업 비중 증가와 배속 하락의 연관성을 보여 주며, 시뮬레이션 600초 자체가 원인임을 입증하지는 않는다.

기존 `MaxSubstepDeltaTime=0.008333`은 잘린 소수다. Chaos가 `ceil(dt / max_dt)`로 횟수를 정하므로 1/60초 프레임에 3단계가 발생한다. 설정을 float 표현의 1/120초에 맞는 `0.008333334`로 수정하여 의도한 2단계를 사용한다. 배속 드라이버에서는 이미 실행 중인 설정의 알려진 기존 값도 정규화하며 다른 사용자 설정값은 유지한다. 일반 월드 경로의 새 설정은 에디터를 재시작하면 적용된다.

`PortSim.InlineBatchPhysics` 기본값은 1이다. 지원되는 standalone·동기 물리의 배속 묶음에서만 해당 Chaos 솔버의 dispatch를 SingleThread 모드로 실행하고 종료 시 이전 모드로 복구한다. 제어 단계마다 결과를 기다려야 하는 구조에서 불필요한 작업 스레드 예약·대기를 줄이기 위한 변경이다. 충돌 접촉, 구속 반복 횟수, 기존 안정화 조건, 바람·항력은 유지한다. 값 0은 기존 dispatch 경로로 비교할 때 사용할 수 있다. 알 수 없는 물리 구성 요소가 있으면 적용하지 않는다. 정지한 몸체에 정확히 0인 힘만 전달하지 않으며, 비영 힘을 무시하는 임계값은 추가하지 않았다.

`PORTSIM_PHYSICS_COST` 로그에는 시뮬레이션 시간, 구간 내 최대 자유 화물 수, 실제 물리 호출 횟수, 호출당 솔버 비용, 충돌 후보 동기화 비용, 전환 동기화 총 비용, inline 적용 여부와 세부 단계 간격을 기록한다. 누적 화물 수 증가인지 접촉 계산인지 스레드 대기인지 후속 실행에서 구분할 수 있다. 실행 테스트는 수행하지 않았으며, 수정 후 실제 배속은 미측정이다.
