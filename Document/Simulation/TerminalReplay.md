# 터미널 체크포인트 배속 재생

기준일: 2026-11-01. 통합 터미널의 현재 배속 동작과 검증 범위다. Chaos 내부 상태 복원은 제외한다. **장시간 고부하에서 설정 배속을 일정하게 유지하는 목표는 미완료다.**

## 동작과 지연 처리

환경·센서·제어기·배차·예약·화물 운동을 1/60초 간격으로 먼저 계산하고, 저장한 체크포인트를 60Hz 목표로 재생한다. 요청 8배속이면 기본 화면 묶음은 8단계, 16배속이면 16단계다. 물리 계산 간격은 배속이나 화면 지연에 따라 늘리지 않는다.

실제 경과 시간 × 요청 배속으로 진행할 시간을 누적한다. 프레임이 지연되면 필요한 단계 수에 맞춰 미래 버퍼와 계산 예산을 늘리고, 미처리 시간은 다음 프레임으로 이월한다. 한 화면에서 소비하는 단계는 최대 960개다. 계산하지 않은 미래로 건너뛰지 않는다.

2026-10-31에는 재생 경로의 50ms 제한, 호출부의 100ms 제한, 버퍼 소진 시 미처리 시간을 버리던 처리를 제거했다. 이 수정은 지연 때문에 진행 시간이 누락되는 문제를 해결한다. 지속적으로 계산 성능이 부족한 경우 요청 배속이나 화면 60fps 달성을 보장하지는 않는다.

사전 계산은 게임 스레드 안에서 수행한다. UObject를 작업 스레드에서 변경하지 않는다. 미래 계산 후 표시할 체크포인트로 한 번 복원하고, 재생할 결과만 확정한다. 이미 표시 시점이 지난 중간 화면은 저장하지 않지만, 해당 모델 단계와 확정 로그는 모두 처리한다. 별도 프로세스나 전체 운송 종료까지의 일괄 계산 방식은 아니다.

## 입력과 실시간 경로 전환

환경 setter, 승인된 대시보드 장비 명령, 초기화 및 연결된 에디터 속성 변경은 미래 버퍼를 즉시 폐기한다. 현재 표시 상태에 입력을 적용하고, 요청 배속은 보존한 채 마지막 입력 후 실제 시간 2초 동안 1배속으로 실행한다. 이후 새 조건의 체크포인트 재생으로 복귀한다. 자연적인 환경 변화는 외부 입력으로 취급하지 않는다. 새 입력 경로에는 `NotifyExternalSimulationInput` 연결이 필요하다.

입력·일시정지 등 기존 무효화 경계에서는 누적 시간을 초기화한다. 정지 시간을 재개 후 몰아서 재생하지 않는다.

월드에 물리 시뮬레이션 중인 몸체가 있으면 수면 중이어도 사전 계산을 사용하지 않는다. 계산 중 화물이 자유 물체로 전환되면 아직 물리가 실행되지 않은 묶음의 안전한 앞부분만 보존한다. 실제 해제 단계는 실시간으로 한 번 실행한다. Chaos 접촉·구속·수면 이력은 캡처하거나 되감지 않는다.

자유 강체가 모두 해당 터미널의 정적 메시 화물이고 standalone·동기 물리 조건을 만족하면, `PortSim.BatchLivePhysics`로 실제 물리를 순방향으로 묶어 실행할 수 있다. 매 1/60초 모델 단계 뒤에 Chaos 계산과 결과 동기화를 완료한 후 다음 센서·제어 단계를 실행한다. 한 화면의 상한은 120단계(시뮬레이션 2초)이며 남은 시간은 이월한다. 바깥 엔진 물리 프레임은 시간 0으로 동기화하여 중복 적분을 방지한다. 웹 명령은 묶음 시작 전에 확인하고 관제 출력은 완료된 묶음 뒤에 수집한다.

외부 자유 강체, 비정적 메시 자유 강체, 네트워크 월드, 비동기 물리·물리 예측에서는 기존 고정 단계 실행을 사용한다. 이 경로도 누적 시간을 버리지 않지만 한 엔진 프레임에 한 단계만 처리하므로 지속 부하에서는 요청 배속보다 느릴 수 있다. 다시 지원 경로에 진입하면 남은 시간을 보충한다.

기존 실시간 실행의 화면 그리기는 벽시계 간격과 요청 배속에 필요한 고정 단계 수를 모두 만족한 뒤 수행한다. 느린 화면 그리기 직후 매 물리 단계마다 다시 화면을 그리던 악순환을 막는다. 정적인 터미널 표지판은 최초 한 번 렌더링한 뒤 반복 tick을 끈다. 한 프레임에 교통 단계가 하나뿐이면 화물 외형의 일괄 분리·재부착도 생략한다.

## 복원과 출력

체크포인트는 환경 난수·누적 상태, 제어기·센서·현수체, AGV 동역학, 화물 운동·소유권, 작업·예약·진행 시간·보고서 상태와 장면의 이동 가능한 구성 요소를 보관한다. 객체 참조가 만료되어 복원이 불가능하면 작업을 중지한다.

미래 계산 중 로그·보고서·대시보드 공개를 보류하고, 재생 시점에 확정한 결과만 공개한다. 실제 배속은 진행한 시뮬레이션 시간 대비 벽시계 시간으로 측정하며 설정값으로 대체하지 않는다.

## 상태와 설정

- `live`: 일반 실시간 실행 또는 1배속.
- `live_input_hold`: 외부 입력 후 1배속 대기.
- `preparing`: 재생 버퍼 준비 또는 소진 후 준비.
- `replay`: 준비한 체크포인트 재생.
- `live_physics_batch`: 실제 화물 물리를 1/60초씩 순방향으로 묶어 실행.
- `live_chaos`: 지원하지 않는 물리 조건 또는 해제 경계에서 기존 실행 경로 사용.

대시보드는 요청·실제 달성 배속, 모드와 버퍼 시간을 표시한다.

- `PortSim.BufferedPlayback`: 기본 1. 0 또는 실행 인수 `-PortSimNoReplay`로 기존 경로를 선택한다.
- `PortSim.BatchLivePhysics`: 현재 검증용 기본 0. 1 또는 실행 인수 `-PortSimBatchLivePhysics`로 지원 화물의 순방향 물리 묶음 실행을 선택한다.
- `PortSim.ReplayWindowSteps`: 기본 16, 범위 1~60. 기본 목표 버퍼는 화면 묶음 두 개 이상이며 지연 수요에 따라 늘어난다.
- `PortSim.ReplayBudgetSteps`: 기본 16, 범위 1~60. 기본 계산 예산이며 상한이 아니다. 화면 묶음과 경과 시간 수요가 크면 설정값을 초과한다.
- 입력 대기 2초는 `PlaybackInputGate`의 정책이며 콘솔 설정은 아니다.

## 최신 검증 — 2026-11-01

현재까지의 구현을 빌드·문서화한 중간 정리다. UE 5.6 Development Editor 최종 빌드가 성공했고, 최종 빌드의 전체 자동 검사 53개가 모두 `Success`였다. 로그: `PortSim/Saved/Logs/PlaybackBuildDocumentation_Final.log`. 순방향 물리 묶음 실행은 기본값 0인 선택 기능으로 남겨 두었다. 고부하 성능 검증이 끝난 것으로 간주하지 않는다.

배속·물리 회귀 검사는 고정 간격, 화면 그리기 주기, 지연 시간 보존, 실제 중력 운동, 착지 충돌, 분할 실행 일치, 중복 적분 방지, 외부 자유 강체 제외, 2초 계산 상한과 잔여 시간 보존, 일시정지 시 시간 폐기를 포함한다. Dashboard 검사 35개가 통과했다.

선박 3척 × 200개, 초기 야드 재고 0개, 시드 `166290927`, 1280×720 렌더링, 요청 16배속, `-BatchLivePhysics` 조건의 측정:

- 외형 연결 최적화 전: 실제 62.187초 동안 시뮬레이션 183.600초, 평균 **2.952배**, 최저 측정 구간 **2.780배**, 운반 완료 0건. `PortSim/Saved/PlaybackPhysicsBatch_600Probe.json`.
- 외형 연결 최적화 후: 실제 60.163초 동안 시뮬레이션 216.900초, 평균 **3.605배**, 최저 측정 구간 **2.055배**, 운반 완료 0건. 목표의 95% 미만인 구간 6개. 최대 관측 작업 집합 약 **3,147MB**. `PortSim/Saved/PlaybackPhysicsBatch_600Artwork.json`.
- 각 원본 로그는 같은 이름으로 `PortSim/Saved/Logs/`에 있다. 구간은 약 10초마다 기록하지만 계산이 길어지면 기록 시점도 늦어진다. 평균 개선을 일정 배속 달성으로 해석하지 않는다. 두 측정 모두 첫 실제 하역 인계 전이므로 600개 조건의 순방향 물리 성능도 아직 검증되지 않았다.

이전에 저장된 작업 설정으로 수행한 `PlaybackPhysicsBatch_Candidate`는 화물 8개 조건이었다. 60초 평균 16.028배, 최저 구간 15.804배, 운반 2건이었으나 고부하 증거로 사용하지 않는다. 이어진 `PlaybackPhysicsBatch_16xLong.log`도 8건을 모두 처리한 뒤 정지하여 10분 시험을 중단했다. 이를 장시간 배속 또는 메모리 검증 통과로 기록하지 않는다.

측정 스크립트는 이제 저장 설정과 무관하게 기본 선박 3척·척당 200개를 명시한다. 시작 로그의 실제 화물 수가 요청과 다르면 실패하며, 구간별 배속·목표 95% 미달 횟수·메모리 표본을 요약 JSON에 저장한다. 실행 시간은 최대 3,600초까지 지정할 수 있다.

남은 주요 비용은 사전 계산 중 선상 화물 전체의 반복 위치·외형 갱신이다. 이를 모아 반영하려던 마지막 `FScopedMovementUpdate` 실험은 엔진의 스택 전용 수명 제약으로 컴파일되지 않아 현재 코드에서 제거했다. 후속 작업에서는 충돌 질의 결과를 보존하는 별도 설계와 검증이 필요하다. 전체 운반·장시간 8/16배속·메모리 안정성·배속별 물리 동등성은 미완료다.

## 이전 검증 — 2026-10-31

UE 5.6 Development Editor 빌드 성공. `PortSim.Playback` 자동화 4개가 모두 `Success`였다. 로그는 `PortSim/Saved/Logs/PlaybackCadence_Regression.log`다. 엔진 초기화의 기존 `Condition failed` 메시지와 자동화 최종 판정은 구분한다.

- 고정 시계, 관제 수집 주기, 현수체 시제품, 실제 터미널 체크포인트 검사 통과.
- 체크포인트의 위치·센서·예약·화물 소유권·난수 복원, 미래 비노출, 8단계 기준과 8배속 재생 일치, 외부 입력·일시정지·수면 Chaos 제외 검사 통과.
- 100ms 지연 프레임의 8배속 진행과 반복 40/60ms 프레임의 2/4/8/16배속 시간 보존 검사 통과. 프레임별 오차는 화면 묶음 한 개 이내이며 잔여 시간은 보존한다. 교통 시계는 별도 0.05초 간격으로 갱신되므로 프레임별 재생 오차는 확정한 1/60초 단계 기준으로 검사한다.

요청 8배속, 환경 시드 `166290927`, 30초 실행 측정:

- null RHI: 실제 30.001초, 시뮬레이션 240.800초, 평균 **8.026배**. `PortSim/Saved/PlaybackCadence_Perf.json`, `PortSim/Saved/Logs/PlaybackCadence_Perf.log`.
- 1280×720 렌더링 포함: 실제 30.012초, 시뮬레이션 240.850초, 평균 **8.025배**. `PortSim/Saved/PlaybackCadence_Render.json`, `PortSim/Saved/Logs/PlaybackCadence_Render.log`.

두 측정 모두 운반 완료 0건이다. 시작 구간과 이산 시간 측정 오차를 포함한 평균이며 매 순간 정확한 8배속, 화면 60fps 또는 모든 부하에서의 성능 보장을 뜻하지 않는다. 전체 운반 완료, 장시간 고부하·메모리, 배속별 물리 동등성, 실제 렌더링의 2/4/16배속 성능은 추가 검증 대상이다.

## 재현

저장소 루트에서 실행한다.

```powershell
./PortSim/Scripts/BuildPortSim.ps1
./PortSim/Scripts/MeasurePlayback.ps1 -PlaybackRate 8 -Seconds 60
./PortSim/Scripts/MeasurePlayback.ps1 -PlaybackRate 8 -Seconds 60 -Render
./PortSim/Scripts/MeasurePlayback.ps1 -PlaybackRate 16 -Seconds 60 -Render -BatchLivePhysics -Ships 3 -CargoPerShip 200
```

`-Ships`와 `-CargoPerShip`으로 부하를 명시한다(기본 3, 200). `-BatchLivePhysics`는 선택적 순방향 물리 실행, `-SingleThreadedPhysics`는 별도 엔진 진단용이며 기본값이 아니다. `-NoReplay`는 기존 실시간 경로 비교용이다. `-LogPath`와 `-SummaryPath`로 로그·요약 JSON 경로를 지정할 수 있다. 실행 로그와 JSON의 실제 달성 배속으로 판정한다.

## 이전 검증 이력

2026-10-30 초기 체크포인트 재생은 null RHI 요청 8배속에서 실제 20.076초 동안 시뮬레이션 153.350초, **7.638배**였다. `PortSim/Saved/TerminalReplay_Final.json` 및 `PortSim/Saved/Logs/TerminalReplay_Final.log`에 기록했다. 당시 배속 자동화 4개와 Dashboard 테스트 35개가 통과했다. Dashboard 테스트는 2026-10-31 수정에서 다시 실행하지 않았다.

관제 수집 최적화의 7.449배 → 7.702배 기록은 [PlaybackClock.md](PlaybackClock.md)에 보존한다. 서로 다른 날짜·빌드의 측정이므로 최신 결과와 직접 비교해 개선율을 계산하지 않는다.
