# 실행 가능한 작업 우선 배차

## 확인한 문제

기존 120개 운송 기록 `Site_332759EA4978ECA703C58B95022CBA59.csv`에서 C2534의 STS 작업은 2671.9초(44.5분)였다. 이 화물은 895.6초에 작업 후보가 되었지만, 야드 받침 C2174가 3781초에 적재된 뒤 3889.65초에 AGV에 인계됐다. 바닥층인 C2379도 목적 RMG 45번의 접근 공간 때문에 STS 작업 시간이 2660.9초였다. STS가 먼저 인양하고 야드가 준비된 뒤 AGV를 보내는 순서가 원인이었다. 이는 효율 최적화의 결과가 아니라 불필요한 선행 인양과 작업 순서 고정의 영향이다.

## 변경한 결정 순서

1. 동일 선박의 이전 배치와 실제 선박 상부 컨테이너가 제거됐는지 검사한다. 제한된 테스트에서는 기존 의존 순서의 동일한 화물 집합만 처리한다.
2. 그중 해당 크기의 예약 슬롯, 아래층 지지, 20ft 두 아래 자리, RMG 접근 권한 및 인접 인수점 회전 여유가 모두 준비된 화물만 배차 후보로 삼는다.
3. 후보 중 선박에서 꺼낼 수 있게 된 시각이 가장 오래된 요청을 우선하고, 같으면 기존 계획 순서를 따른다. 오래 기다린 작업도 준비되는 즉시 우선순위를 회복한다. 막힌 첫 화물이 다른 RMG로 갈 화물까지 막지 않는다.
4. 실제 빈 AGV와 목적 RMG 접근 권한을 한 번에 확보한 뒤 인양을 시작한다. AGV 접근과 센서 기반 인양은 동시에 진행한다. 인양 중인 STS에는 항상 실제 배정 AGV와 목적 야드 접근 예약이 있어야 한다는 런타임 검사를 추가했다.
5. AGV 선택은 기존 도로 접근 거리와 작업량 차이를 사용한다. 작업량 차이의 가산 비용은 최대 48초로 제한한다. 직접 복귀는 도로 경유 거리로 추정한 도착 시간이 빈 AGV의 접근 시간보다 짧을 때만 선택한다. 복귀 차량의 STS 대기 베이는 유지하되 아직 인양하지 않은 화물은 같은 STS의 다른 준비된 화물로 바꿀 수 있다.

지정된 야드 슬롯·규격별 구역·무게·출고·위험물 조건은 변경하지 않는다. 교통 예약, LiDAR, 차체 및 크레인 다리 겹침, 센서 정렬, 잠금, 시험 권상 조건도 유지한다. 위험물 구역처럼 사용 가능한 RMG가 적은 구간의 처리 용량이나 실제 도로 혼잡은 남을 수 있다. 모든 AGV의 동시 투입이나 전역 최적해를 보장하는 방식은 아니다.

## 관측과 검증

웹 STS 상세에 배차 판단, 즉시 처리 가능한 화물 수, 아래층/RMG 대기 수, 배정 AGV, 인양 후 AGV 대기와 선박 위 선순위 화물의 대기를 표시한다. CSV에는 `DispatchEligibleAtSeconds`, `AGVAssignedAtSeconds`, `DispatchWaitSeconds`, `STSWaitingForAGVSeconds`를 추가했다. 선박 위에서 기다린 시간과 실제 매달린 채 AGV를 기다린 시간을 구분하며, 전체 효율은 동일 화물의 마지막 야드 적재 시각으로 비교한다.

최종 통합 검증 명령:

```powershell
./PortSim/Scripts/TestSite.ps1 -Mode Normal -PlaybackRate 0 -FixedFPS 5 -TimeoutMinutes 120 -CheckStowage -CheckDispatch -DispatchBaselineReport ./PortSim/Saved/Results/Site_332759EA4978ECA703C58B95022CBA59.csv
```

`AssertDispatchReport.ps1`는 같은 화물 ID 집합, 배차 시각/누적 시간, 최대 인양 후 AGV 대기 1200초 미만, 기준보다 짧은 최종 적재 시각을 검사한다. 1200초는 이번 회귀 검사의 상한이며 실제 장비의 안전 허용 시간이 아니다.

- `SiteTest_Normal_25624.log`, `Site_69F2B6504DC93151E419E9840905A5F3.csv`: 동일한 120개(전체 600개의 20%) 실제 운송, 차량 복귀, 일시정지·비상정지·운송 중 초기화·완료 후 초기화 통과.
- 마지막 야드 적재는 **10719.250160 → 9657.200144초**, **9.91% 단축**. 복귀 포함 종료 검사는 9796.7초. 인간 운용 대비 절감률이나 전체 600개 하역의 검증 결과가 아니다.
- 최대 STS 작업 시간은 **2671.9 → 1021.6초**. 새로 분리 계측한 인양 후 AGV 대기는 평균 **13.8초**, 최대 **714.6초**. 최대값은 C2176의 도로 접근 대기이며 긴 대기가 완전히 제거된 것은 아니다.

- 최대 동시 이동 AGV는 **16 → 19대**, 사용 AGV는 **34 → 37대**. 20ft 두 자리 완료 층 15개, 지지된 상부 적재 58개, 경제성이 확인된 두 화물 AGV 운송 2회. 기존 센서·물리·충돌·적재 조건을 유지한 상태의 결과다.

## 4배속 실행

에디터 플레이 중 `+` 두 번(1→2→4), `-`로 감속, `0`으로 1배 복귀. 실행 인수는 `-PortSimPlayback=4`다. 자동 검증 스크립트의 기본값도 `-PlaybackRate 4`로 바꿨다. 기존 고정 시간 간격 비교를 재현할 때는 위 명령처럼 `-PlaybackRate 0`을 사용한다. 4배속은 장비 속도·하중 한계를 바꾸지 않고 공통 시뮬레이션 시계를 가속하며, 실제 달성 배속은 CPU 처리량의 영향을 받는다.

요청 후 별도 4배속 확인도 통과했다. `ReadyDispatch_4x_20261015.log`에서 9개 운송·복귀·일시정지·비상정지·운송 중/완료 후 초기화가 `PORTSIM_SITE_PASS`와 종료 코드 0으로 완료됐다. 스냅샷 `playback_rate=4`를 확인했으며, 이 PC의 화면 없는 실행에서 실제 진행 속도는 약 2~3배였다. 복귀 포함 1597.1 시뮬레이션 초가 걸렸다. 이 짧은 배속 확인은 앞선 동일 120개 성능 비교와 구분한다. 결과 파일은 `Site_4396EF57478934DDC8FB218BC61E8475.csv`다.
