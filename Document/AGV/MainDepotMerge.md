# upstream main AGV 대기소 병합 (2026-10-15)

`junsoo`의 기존 작업을 `b17eab2`로 보존한 뒤 `upstream/main`의 `ef316c3`까지 병합했다. 대기·충전소 60면, 전 차량 대기소 초기 배치, 배터리 배차, 주차장 진출입 수정, 카메라/HUD 및 main의 나머지 변경을 포함한다.

## 충돌 해결

- 기존 두 번째 20ft 개별 적재 단계 10을 유지하고 충전 이동/복귀/충전은 `FSiteTransfer::ToCharge=11`, `ReturnToStandby=12`, `Charging=13`으로 분리했다. 웹 상태 표시도 함께 맞췄다.
- 실행 가능한 화물·야드·AGV를 확보한 뒤 인양하는 배차에 배터리 조건을 함께 적용했다. 직접 복귀 비교에서도 저전력 유휴 차량을 제외한다.
- 유휴 AGV의 접근 비용은 새 주차장 행별 출구와 X=14000 남행 도로를 반영한다.
- 규격별 야드, 20ft 두 자리 지지 조건, 기존 관측 속도 및 수평 흔들림 제동을 유지했다. main의 수직 선박 운동 추종에 권상 상한 제동을 함께 적용했다. RMG 수평 상대속도 설정은 기존의 더 엄격한 0.05m/s를 유지했다.

## 검증 결과와 남은 문제

- UE 5.6 Editor 빌드 성공.
- 네이티브 20개와 웹 9개 테스트 통과. 로그: `PortSim/Saved/Logs/MainDepotMerge_Units_20261015.log`.
- STS 파도 픽업 검사 통과(49.90 시뮬레이션 초). 로그: `PortSim/Saved/Logs/Pickup_STS_wave.log`.
- `TestSite.ps1 -Mode Normal -PlaybackRate 4 -TimeoutMinutes 120 -CheckStowage -CheckDispatch`를 실행했지만, **120개 완료 검증은 통과하지 않았다.**
- 시뮬레이션 4623.337초, **82개 적재**에서 이 검증 프로세스를 중단했다. V119와 V135가 서로를 막는 동일 위치의 기록이 13:17부터 13:22 UTC까지 반복됐다. 다른 차량은 적재를 계속했으므로 터미널 전체 정지로 해석하지 않는다.
- V119: 적재 주행 단계 3, 위치 약 `(138.8798, -133.3889)m`, LiDAR 정지. V135: 적재 주행 단계 3, 위치 약 `(147.2525, -124.8185)m`, FMS 대기. 서로의 차량 ID를 blocker로 기록한다. 기존 정지 차량 재진입 로직만으로 이 쌍의 진행이 회복되지 않았다.
- 재현 로그: `PortSim/Saved/Logs/SiteTest_Normal_24152.log`. 중단 직전 스냅샷: `PortSim/Saved/Tests/MainDepotMerge_20261015/deadlock_state.json`.

이 결과는 병합 완료와 전체 운송 검증 통과를 구분한다. 교착의 main 단독 원인 여부는 비교 검증하지 않았으며, 이 병합에서 적재 차량 교착 해결을 완료한 것으로 표시하지 않는다. 충전 임계값까지의 장시간 배터리 순환도 이번 운송 실행에서 검증하지 않았다.
