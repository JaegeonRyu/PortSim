# 적재 AGV 교착 복구와 주차 방식 비교

## 교착 수정

기록된 V119·V135 교착은 적재 차량과 LiDAR 안전정지가 포함돼 있었다. 기존 후진 복구는 공차의 FMS 대기만 추적했으므로 이 사이클을 처리하지 못했다. 미래 도로 예약을 다시 허용하는 것만으로는 서로 가까이 선 차량의 실물 위치가 바뀌지 않았다.

- FMS 대기와 LiDAR 정지를 함께 추적한다.
- 직선 서비스 도로 위에서 정차했고 RMG 인수 구간을 아직 점유하지 않은 적재 주행 차량도 양보 후진 대상으로 삼는다. 적재 한도, 도로 경계, 후방 차량 및 도로 예약을 확인한다.
- 보수적인 도로 여유 영역 안에서 이미 정지한 경우에는 상대에서 멀어지는 방향으로만 탈출한다. 전체 차체 후진 궤적이 비어 있어야 하며 기존 실물 차체 겹침 검사는 유지한다.
- 원래 조향·전후진·가속도·LiDAR 제어로 최대 20m 후진한다. 순간이동이나 좌우 이동을 추가하지 않았다. 적재물의 부모·소유권·하중을 유지한다.
- 후진을 마치자마자 다시 진입하지 않고, 양보받은 차량이 실제 경로를 벗어날 때까지 기다린다.

`PortSim.Traffic.LoadedLiDARDeadlockRecovery`는 기록된 두 차량의 위치·방향을 작은 테스트 월드에 재현한다. 12t 적재 상태의 후진 완료, 후방 장애물 거부, 횡방향 미끄러짐 없음, 화물 부착·소유권 유지, 상대 통과 전 양보 및 통과 후 해제를 검사한다. 테스트 월드에서는 연속 차량 인덱스를 위해 ID 100/101을 사용한다.

## 비교 조건

수정된 같은 UE 5.6 엔진에서 이전 3열 분산 주차·출차 규칙을 `-PortSimLegacyParking`으로 재현하고, 새 60면 대기·충전소 방식과 비교했다. 정상 실행의 기본값은 새 주차장이다. 이전 커밋의 다른 크레인·환경 변경까지 섞은 비교가 아니다.

- 선박 3척 × 200개 중 동일한 **120개(전체의 20%)**를 실제 야드에 적재했다.
- 화물 ID·크기·무게·야드 슬롯·층·RMG·출고·위험물 계획이 같은지 비교 스크립트가 검사한다.
- 환경 난수 `166290927`, 고정 프레임 0.2초(`FixedFPS=5`, `PlaybackRate=0`). 파도 및 돌풍 로그도 일치한다. 벽시계 실행 속도나 배속 차이를 시간 절감으로 계산하지 않는다. 일반 자동 검증의 기본 4배속 설정은 유지한다.
- 두 방식 모두 동일한 센서·하중·조향·충돌·적재·배차 준비 조건과 같은 교착 수정 코드를 사용했다.

재실행:

```powershell
./PortSim/Scripts/CompareAGVParking.ps1 -EnvironmentSeed 166290927 -FixedFPS 5 -TimeoutMinutes 120
```

이 조건에서는 새 주차장이 최종 적재 기준 **363.90초(6.07분), 3.93% 느렸다.** 복귀 포함 종료도 342.9초, 3.65% 느렸다. 차량 투입과 작업 분산이 늘어난 결과를 총 하역 시간 개선으로 해석할 수 없다.

마지막 화물 C2582는 C2510 위에 놓인다. C2510 적재는 이전 방식 7796.400116초, 새 방식 8892.900133초였다. C2582 시작은 8545.400127 → 8908.200133초로 362.80초 늦었고, 시작부터 최종 적재까지의 차이는 약 1.10초였다. 따라서 이번 최종 시간 차이는 마지막 운송 자체의 속도보다 선행 적재·배차 준비 시각 지연에서 대부분 발생했다. 이 기록만으로 전체 차이의 유일한 원인을 주차장 거리로 단정하지 않는다.

교통 대기는 CSV `TrafficWaitSeconds` 기록값으로, FMS 도로 예약 및 양보 대기를 포함하며 모든 LiDAR 정지·유휴 시간을 합한 값은 아니다. 이 비교는 단일 환경 난수의 120개 시나리오 결과이며 전체 600개 완료 시간이나 장시간 충전 순환의 결과가 아니다.
