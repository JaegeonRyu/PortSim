# STS 픽업 차량의 도로 진입 우선순위

## 문제와 범위

기존 도로 진입은 실제 도로 요청 대기시간 순서였다. 주차장 복귀와 STS 픽업을 구분하지 않아, 빈 차량이 많아도 배정된 픽업 AGV가 복귀 차량 뒤에서 기다릴 수 있었다. `PortSim.log`의 2026-10-20 실행에는 픽업 V106(stage 6)이 주차장 복귀 V139(stage 5)에 막힌 사례가 있다. 같은 실행의 마지막 스냅샷은 104개 완료, 유휴 32대였다. RMG 작업 대기도 함께 관측되어 교통 우선순위만으로 모든 병목이 해소된다고 가정하지 않는다.

배차 대수, STS별 작업 소유권, 야드 지지·규격·위험물 예약, AGV 속도·조향·마찰·LiDAR 조건은 유지한다. 실제 배정된 차량의 도로 진입과 가까운 합류 지점에만 우대한다.

## 계산

도로 대기 시작 시각에서 다음 가산점(시뮬레이션 초)을 뺀 가상 요청 시각이 이른 차량부터 처리한다. 아직 막히지 않은 요청의 시각은 현재 교통 시각이다.

| 목적 | 가산점 |
|---|---:|
| STS 픽업으로 이동(stage 6/7), 다음 STS 작업을 배정받은 직접 복귀(stage 5) | 20초 |
| 위 픽업 대상 STS가 실제로 해당 화물을 들고 AGV를 기다림 | 추가 `min(실제 인양 후 AGV 대기초 × 0.1, 20초)` |
| 화물을 받은 뒤 STS 인수 공간을 아직 점유하며 출발(stage 3) | 40초 |
| 주차장 복귀·충전 이동 및 기타 | 0초 |

최대 가산점은 40초다. 신규 픽업보다 충분히 오래 기다린 복귀 요청이 이길 수 있고, 같은 가상 시각에서는 기존 대기 순서와 결정적인 tie-break를 사용한다. 화물 준비 시각을 도로 대기시간으로 대체하지 않는다. 이 규칙은 진행 순서 정렬과 미진입 합류 요청 간 비교에 공통 적용한다.

합류 대기 영역은 기존 RMG→주도로 합류에만 등록하며, 기존 30초 대기 기준과 60m 주변 경계를 유지한다. 픽업 출발 차량에 새 대기 영역을 추가하지 않는다. 새 정책은 예약 경쟁의 비교 순서에만 적용한다. 긴 미래 경로나 직진 추종 대기열은 등록하지 않는다.

이미 승인된 구간의 예약을 취소하거나 진입 중인 차량을 밀어내지 않는다. 차체·장애물 검사, 출구 공간 확보, LiDAR 안전 정지와 교착 복구는 유지한다. 합류 영역 안의 차량은 먼저 빠져나갈 수 있다. 우선순위는 예약 경쟁을 개선하며 물리적으로 막힌 차선을 비워 주지는 않는다.

## 관측과 비교

웹 원본 텔레메트리에는 루트 `agv_road_priority`(`pickup_with_aging`/`fifo`), AGV별 `road_priority_bonus_seconds`, `road_request_wait_seconds`를 기록한다. 기존 CSV의 인양 후 AGV 대기, 도로 대기, 최종 야드 적재 시각으로 효과를 판단한다.

기존 FIFO는 `-PortSimLegacyRoadPriority`로 재현한다. 두 비교 실행은 동일 바이너리, 600개 중 동일한 120개 작업, 도로·주차장·날씨·시드·고정 간격을 사용한다. `-NoSea`는 기존 선박 운동 정합성 문제를 분리하기 위한 시험 조건이다.

```powershell
./PortSim/Scripts/TestSite.ps1 -Mode Normal -PlaybackRate 0 -FixedFPS 5 -TimeoutMinutes 60 -NoSea -LegacyRoadPriority -CheckStowage -ResultSummaryPath ./PortSim/Saved/Tests/PickupPriority_FIFO.json
./PortSim/Scripts/TestSite.ps1 -Mode Normal -PlaybackRate 0 -FixedFPS 5 -TimeoutMinutes 60 -NoSea -CheckStowage -ResultSummaryPath ./PortSim/Saved/Tests/PickupPriority_Weighted.json
```

이는 대기 없는 고정 시간 간격 비교다. 실제 화면의 4배속과 장비 이동 속도는 변경하지 않는다. 변경 후 개선율은 완료된 비교 결과가 있을 때만 기록한다.

## 2026-10-20 검증 결과

UE 5.6 빌드와 네이티브 32개·웹 12개 테스트를 통과했다. 픽업/직접 복귀/충전 복귀/STS 출발 역할 구분, 대기시간에 의한 복귀 차량의 순위 회복, 결정적·추이적인 순위 비교를 포함한다. 네이티브 로그는 `PortSim/Saved/Logs/PickupPriority_Units_20261020_145810.log`다.

첫 변경 실행은 픽업 출발 차량에 새 합류 대기 영역과 짧은 보호 시작 시간을 추가한 실험이었다. 84개에서 주차장 입·출구 교착을 확인해 중지했다(`SiteTest_Normal_Depot_Reused_22032.log`). 이 확장은 제거했다. 최종 버전은 기존 합류 영역과 30초 대기 기준을 유지하고 요청의 비교 순위만 바꾼다. 실패한 변경 실행만 다시 운송 검증했으며, 통과한 FIFO 기준 운송은 반복하지 않았다.

두 완료 실행은 동일 600개 중 **동일 ID 120개(20%)**, 같은 무게·예약 야드 슬롯·규격·위험물 계획, Depot/Reused 도로, 시드 166290927, 고정 간격 0.2초, 건조 노면, 선박 운동 OFF 조건이다. 기준 실행 후 CSV 프로필에 정책명을 기록하는 항목만 보완했다. 운송 제어 로직의 다른 변경 없이 A/B 플래그로 정책을 구분했다.

| 지표 (시뮬레이션 초) | FIFO | 픽업 우대 | 변화 |
|---|---:|---:|---:|
| 마지막 STS→AGV 인계 | 8,823.05 | 8,469.95 | 4.00% 단축 |
| 마지막 야드 적재 | 9,432.65 | 9,080.75 | 3.73% 단축 |
| AGV 복귀 포함 | 9,626.5 | 9,274.1 | 3.66% 단축 |
| 최대 인양 후 AGV 대기 | 867.45 | 439.55 | 49.33% 감소 |
| 평균 인양 후 AGV 대기 | 34.41 | 39.98 | 16.20% 증가 |
| 컨테이너별 도로 대기 합계 | 11,056.30 | 11,327.60 | 2.45% 증가 |

양쪽 모두 9개 STS와 AGV 54대가 참여했고, 20ft 두 자리 완료 층 13개와 지지된 상부 적재 58개를 확인했다. 전체 완료와 가장 긴 STS 대기는 개선됐지만 모든 대기를 줄인 것은 아니다. 특히 평균 대기와 누적 도로 대기는 증가했으므로 균일한 개선이나 전역 최적해로 해석하지 않는다. 같은 120개 작업의 결과이며 전체 600개 완전 하역이나 강우·결빙 조건의 개선율을 보장하지 않는다.

- 기준 원본: `PortSim/Saved/Results/Site_7CE01E3C4C83D4F3BF4AE682CA06FD23.csv`, `PortSim/Saved/Logs/SiteTest_Normal_Depot_Reused_31628.log`.
- 변경 원본: `PortSim/Saved/Results/Site_D4967C454F5F2E248240E1B2CA03BDCD.csv`, `PortSim/Saved/Logs/SiteTest_Normal_Depot_Reused_2804.log`.
- 비교 요약: `PortSim/Saved/Tests/PickupPriority_Comparison.json`.

기준 실행은 엔진의 `PORTSIM_SITE_PASS`와 적재 검사까지 통과했지만, 래퍼 스크립트가 당시 CSV 프로필에 없던 정책명 필드를 검사하며 중단됐다. 실행 인수 로그의 `-PortSimLegacyRoadPriority`와 원본 결과를 확인해 요약을 복구했으며 원본 CSV는 변경하지 않았다. 최종 변경 실행에서는 정책명 기록을 포함한 래퍼 검사까지 통과했다.
