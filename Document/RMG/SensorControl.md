# RMG 센서 기반 운반

## 자료와 선택 사양

자료: `konecranes_rmg_tech_document_final_nov_2023.pdf`, Konecranes, 2023년 11월. 제품군 브로셔이며 특정 설치 장비의 제작 도면이 아니다.

RTG 그림은 sway sensor, bay sensor, encoder, stack profile 등의 기능 배치 참고다. RMG 실측 자료로 취급하지 않는다. 자기유도 자동 조향은 레일 주행 RMG에 적용하지 않는다.

`PortSim/Config/RMG_Simulation.json`에 제품 범위, 선택 사양, 미확인 설치·동역학 가정을 구분했다. XYZ, FOV, 거리 범위, 센서 주기, 오차 허용치, 모터 내부 제원, 로프 물성은 가정이다. 설치된 카메라가 실제 자동 위치 인식 성능을 제공한다는 제조사 주장으로 해석하지 않는다.

## 제어 흐름

통합 터미널의 `APortWorkingCrane` RMG에 적용한다. 과거 전시용 `APortRMGActor`는 별도다.

1. AGV가 정지하고 인계 위치·방향이 일치해야 접근한다. 사이트 배차기는 실제 인계 AGV를 RMG에 전달한다.
   - 한 센서 주기의 일시적인 불일치는 현재 자세에서 하중을 유지하며 다시 확인한다. `alignment_timeout_s`까지 위치·속도·방향·LiDAR 조건이 회복되지 않으면 RMG 픽업을 안전 오류로 정지한다.
2. 슬롯은 접근 목표이며, 최종 정렬은 가상 카메라의 관측 위치·상대 속도와 코너 오차로 계산한다.
3. 네 코너 연속 접촉 → 개별 잠금 명령 → 장치 작동 지연 → 네 잠금 피드백을 확인한다.
4. 위치를 순간 보정하지 않고 현재 위치에서 연결한다. 30 cm 시험 인양으로 지지 해제, 코너별 하중, 추정 질량·무게중심 안정성을 확인한다.
5. 부하 권상 속도·가속도·모터 제한과 흔들림 피드백을 적용하여 야드로 이동한다.
6. 적재 접근 시 트롤리 센서 범위 내 목적지 네 코너의 지지면 높이를 광선으로 측정한다. 예약 높이와 불일치하거나 관측이 없으면 화물을 유지한 채 정지한다.
7. 실제 화물 지지·낮은 속도·위치 허용 오차가 연속 확인되어야 잠금을 해제하고 적재한다.

보기 레이저는 다른 작업 크레인을 관측하며, 속도·감속도·센서 지연으로 계산한 정지 거리와 여유 거리 안에 들어오면 정지한다. 이 인터록의 정지는 시뮬레이터 비상 정지이며, 실제 브레이크 과도응답을 해석하지 않는다. 사람·차량 전체 안전 스캐너나 경로 전체 장애물 회피 기능은 아니다. 야드 프로파일은 목적지 4점 검사이며 전체 스택 포인트클라우드가 아니다.

배경 야드 컨테이너는 충돌이 없는 인스턴스 메시이므로, 기존 예약 시스템이 만드는 고정 받침을 적재 지지면의 대리 형상으로 유지한다. 프로파일 광선은 이 받침과 충돌 가능한 액터를 관측한다. 따라서 배경 야드 전체의 누락·기울기·변형을 독립적으로 재구성하는 센서는 아니다. 예약 데이터와 별개인 실측 적재면 검증에는 배경 스택의 충돌/센서용 형상을 추가해야 한다.

공통 코드의 `FSTSOperatingProfile`, `FSTSObservation`, `FSTSPickupController` 이름은 유지했지만 RMG는 `LoadRMG`로 독립 설정을 읽는다. STS 제조사 수치나 설치 좌표를 RMG 설정으로 가져오지 않는다. 둘 모두 센서·제어·물리를 최대 1/60초 구간으로 진행한다.

수평 이동 제어는 트롤리·갠트리 엔코더와 설정의 위치·속도 이득, sway-rate 피드백을 함께 사용한다. 스프레더 관측은 최종 도달·픽업 판정에 사용하며 현수체 편위를 이동축 위치로 중복 피드백하지 않는다. 목표 부근 완료 판정은 픽업 코너 허용치와 착지 위치·속도 허용치에 맞춘다. 센서보다 과도하게 엄격했던 0.5 cm·0.5 cm/s 고정 판정은 사용하지 않는다. 권상·트롤리·갠트리 최고 속도와 가속도는 선택한 공개 사양 범위를 그대로 유지한다.

## 선적 시 RMG → AGV 인계 (2026-11-03)

야드 화물을 AGV에 내려놓는 역방향 작업은 **안전 조건 검증 → AGV 고정 → 스프레더 잠금 해제 → AGV 출발과 빈 스프레더 상승** 순서로 진행한다. 기존처럼 자유 물리 상태로 내려놓고 RMG 상승·후속 안착 검사가 모두 끝날 때까지 AGV를 대기시키지 않는다.

1. 착지 단계(`Stage==5`)에서 지지·화물 위치·낮은 스프레더 속도가 설정된 `SettleTime` 동안 유지되어야 한다.
2. `SecureRMGToAGV`는 유효하고 최신인 관측, AGV 정렬·정지, 화물 지지·안착, 스프레더 네 잠금 피드백을 확인한다. 실제 AGV 위치와 네 코너 지지 광선을 다시 검사하며, 지지면은 인계 대상 AGV여야 한다. 화물 위치 오차는 `LandingTolerance`와 10 cm 중 작은 값 이내, 상방 벡터 Z는 0.99 이상이어야 한다. 화물이 아직 RMG에 연결되어 있고 자유 물리가 꺼져 있으며 목적지가 비어 있는지도 검사한다.
3. 조건이 충족되면 측정된 화물 자세를 유지한 채 AGV 루트에 강체 부착한다. 부착 성공과 부모 액터를 확인한 다음 소유권을 `ECargoOwner::AGV`로 이전하고 AGV 적재 질량을 설정한다. 위치를 순간 보정하거나 중간에 자유 물리 상태로 전환하지 않는다.
4. 인계 완료 플래그(`bAGVHandoverComplete`)를 설정한 뒤 스프레더 잠금을 해제하고 빈 권상 단계(`Stage==6`)로 진행한다. `AdvanceExport`는 이 플래그와 실제 AGV 부착·물리 비활성화·소유권·위치·정지 상태를 확인한 시점에 복귀 경로를 배정한다. AGV 주행은 기존 도로 예약과 교통 제어를 따른다.
5. RMG는 AGV 출발 후에도 빈 스프레더 상승을 계속한다. 인계가 끝난 작업에는 AGV 정렬 대기를 적용하지 않고, 완료 단계(`Stage==7`)에서 떠난 화물을 이전 착지 좌표와 대조하지 않는다. RMG 작업 자체는 상승 완료까지 활성 상태로 유지되므로 새 작업이 이를 덮어쓰지 않는다.

안전 조건이 부족하면 인계를 완료하지 않고 착지 대기 시간을 초기화한다. 화물은 RMG에 유지되며 기존 센서·정렬·단계 시간 제한과 고장 처리가 적용된다. AGV 고정 시도 실패는 안전 오류로 정지한다. 인계 완료 상태는 작업 초기화 시 해제하고, 배속 재생 체크포인트에도 저장·복원한다.

여기서 **AGV 화물 고정은 검증된 강체 부착으로 표현하는 시뮬레이션 모델**이다. 네 잠금 피드백은 스프레더의 관측값이며, 별도의 AGV 잠금 액추에이터·센서 모델을 추가한 것은 아니다.

구현: `WorkingCraneRMG.cpp`, `PortWorkingCrane.cpp/.h`, `WorkingCraneSTS.cpp`, `ExportOperations.cpp`, `TerminalCheckpoint.cpp`.

### 검증 기록 (2026-11-03)

- UE 5.6 `PortSimEditor Win64 Development` 빌드 성공.
- `PortSim.RMG.*`와 `PortSim.Playback.*` 자동화 테스트 7개 통과. 로그: `PortSim/Saved/Logs/RMGHandover.log`.
- `PortSim.RMG.AGVHandover`는 지지·안착·잠금 확인 누락, 이동 중인 AGV, 실제 지지면 이탈 시 인계 거절과 기존 RMG 부착 유지를 검사한다. 정상 인계에서는 AGV 부착·소유권·적재 질량을 확인한다.
- 강화한 인계 테스트를 다시 빌드·실행해 AGV 출발 후 실제 스프레더 높이 증가, 화물이 RMG를 따라 움직이지 않음, AGV 위치와 무관한 RMG 완료를 확인했다. 로그: `PortSim/Saved/Logs/RMGHandoverFinal.log`.
- 이 변경의 검증 범위는 위 자동화 테스트이며, 전체 선적 운송 완료나 처리량 개선을 측정한 결과는 아니다.

## 웹

장비 탐색기 → 야드 크레인 → 장비 선택. 개요에서 픽업 단계·하중, 센서 탭에서 접촉·잠금·AGV 정렬·적재면·충돌 상태, 물리 탭에서 가정 기반 장력·토크·흔들림을 확인한다. 변수 탭에 RMG 적용 프로파일과 자료 출처가 표시된다. 센서 페이지 조회 장비 목록에서도 RMG를 선택할 수 있다. 새 빌드 실행 이후의 텔레메트리가 필요하다.

## 재현

```powershell
./PortSim/Scripts/BuildPortSim.ps1
./PortSim/Scripts/TestRMG.ps1
./PortSim/Scripts/TestPickup.ps1 -Crane RMG -Case eccentric -SimulationFrameSeconds 0.62
./PortSim/Scripts/TestSTS.ps1 -Mode Profile
./PortSim/Scripts/TestSite.ps1 -Mode Normal
```

RMG 집중 시험은 AGV에 실린 편차 화물의 최종 야드 적재와 편심 질량 추정, 관측 편향·회전·접촉·잠금·센서 오류, AGV 이동, 적재면 오류, 인접 크레인 충돌을 구분한다. 정상 픽업만 성공했다고 최종 적재 완료로 간주하지 않는다.

편심 시험에서 기존 `SetCenterOfMass`에 입력한 cm 값이 메시 스케일로 다시 확대되는 문제를 발견했다. 물리 엔진에 전달할 때 스케일을 보정하며, 실제 물리 무게중심과 입력 cm 값의 일치를 시험한다.

느린 PC의 통합 회귀는 `TestSite.ps1 -Mode Normal -FixedFPS 1 -TimeoutMinutes 60`으로 실행할 수 있다. Unreal의 델타 시간 제한 때문에 FPS 인자의 역수가 실제 시뮬레이션 간격과 같지 않을 수 있다. 로그의 `SITE_TEST_STEP`을 확인한다.

## 목표 부근 수렴 개선 (2026-09-29)

수평 이동축은 엔코더 위치로 폐루프 제어하고 스프레더 카메라·sway 센서는 최종 도달 판정에 사용하도록 역할을 분리했다. 센서 허용치보다 엄격했던 0.5 cm·0.5 cm/s 고정 완료 조건은 픽업·착지 설정값에 맞췄다. 정격 속도·가속도, 네 코너 착좌, 개별 잠금, 시험 인양과 하중 검증은 유지한다.

같은 24 t 편심 화물(X=25 cm, Y=-80 cm), 0.62초 외부 프레임 조건에서 RMG 인양부터 최종 야드 적재까지 409.2초에서 167.4초로 감소했다(약 59.1%). STS 픽업 검증은 96.1초에서 32.24초로 감소했다(약 66.5%). 이는 집중 시험의 시뮬레이션 시간 비교이며 실제 장비 처리시간 보증값은 아니다. 공유 동역학 시험, STS/RMG 편심 통합 시험, 웹 시험 9개가 통과했다. 토큰·실행 시간을 줄이기 위해 이 변경 후 전체 120개 사이트 시험은 반복하지 않았다.
